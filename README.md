# תרגיל למידת מכונה – רגרסיה לינארית ורגרסיה לוגיסטית

פתרון מלא לתרגיל `תרגיל למידת מכונה.pdf` בשני חלקים:

| חלק | בעיה | מודל | תוצאה מרכזית (סט מבחן) |
|---|---|---|---|
| א | ניבוי מחירי דירות | רגרסיה לינארית | R² = 0.584 |
| ב | הערכת סיכון להתקף לב | רגרסיה לוגיסטית | ROC-AUC = 0.911, Recall = 0.906 |

הפתרון מוצג בשתי דרכים:
- **אפליקציית Streamlit** (`app.py`) – שני חלקי התרגיל, עם חקירת נתונים, בניית מודל, הערכה ופרדיקציה.
- **דשבורד HTML עצמאי לחלק ב** (`heart_dashboard.html`) – מחשבון סיכון להתקף לב שנפתח בדפדפן בלי התקנות.

## חלק א – ניבוי מחירי דירות (רגרסיה לינארית)

**נתונים:** `Project housing data .csv` – 2,999 דירות, 12 עמודות, ללא ערכים חסרים.

**הכנת הנתונים:**
- `view` (0–4) ו-`condition` (1–5) קודדו ב-One-Hot Encoding (`drop_first`).
- `yr_built` הומר לגיל הבית (`house_age`).
- `sqft_above` הוסר כי `sqft_living = sqft_above + sqft_basement` בדיוק (מולטיקולינאריות מלאה).
- חלוקה אקראית 80% אימון / 20% מבחן, `random_state=42`.

**ביצועים על סט המבחן:**

| מדד | ערך |
|---|---|
| R² | 0.584 |
| MAE | $148,055 |
| RMSE | $204,654 |
| MAPE | 32.3% |

**פרדיקציה:** דירה בדויה – 3 חדרי שינה, 2 חדרי רחצה, 2,000 sqft (מהם 400 מרתף), מגרש 7,500 sqft, 2 קומות, בנויה ב-1985, מצב 3, בלי נוף ובלי חוף → **כ-$489,000**. המחיר נמצא בטווח המחירים של דירות דומות בנתונים, ולכן נראה סביר.

## חלק ב – הערכת סיכון להתקף לב (רגרסיה לוגיסטית)

**נתונים:** `heart_data.csv` – מאגר UCI Heart Disease (Cleveland), 303 מטופלים, עם המשתנים שמופיעים בתרגיל בלבד (`trestbps`→`trtbps`, `restecg`→`rest_ecg`).

| משתנה | משמעות |
|---|---|
| `age` | גיל |
| `sex` | מין (1 = זכר, 0 = נקבה) |
| `cp` | סוג כאב בחזה (0–3) |
| `trtbps` | לחץ דם במנוחה (mm Hg) |
| `chol` | כולסטרול (mg/dl) |
| `fbs` | סוכר בצום מעל 120 mg/dl (1 = כן) |
| `rest_ecg` | אק"ג במנוחה (0–2) |
| `thalach` | דופק מקסימלי במאמץ |
| `exang` | תעוקה בזמן מאמץ (1 = כן) |
| `ca` | מספר כלי דם עיקריים שנצבעו בצנתור (0–3) |
| `target` | 1 = סיכוי גבוה להתקף לב |

**בניית המודל:**
1. **ניקוי** – הוסרו 5 שורות עם `ca=4` (ערך לא חוקי) → 298 מטופלים.
2. **קידוד** – `cp` ו-`rest_ecg` הם קטגוריות ולכן קודדו ב-One-Hot; `sex`, `exang`, `fbs` כבר בינאריים; `ca` נשאר מספרי.
3. **חלוקה אקראית** – 238 מטופלים לאימון (80%) ו-60 למבחן (20%), `random_state=42`, עם stratify לשמירת יחס החולים.
4. **נרמול** – `StandardScaler` שנלמד על סט האימון בלבד.
5. **אימון** – `LogisticRegression` של scikit-learn.

**ביצועים על סט המבחן (סף החלטה 0.5):**

| Precision | Recall | F1 Score | ROC-AUC | Accuracy |
|---|---|---|---|---|
| 0.806 | 0.906 | 0.853 | 0.911 | 0.833 |

| | המודל: בסיכון | המודל: לא בסיכון |
|---|---|---|
| **בפועל: בסיכון** | 29 (TP) | 3 (FN) |
| **בפועל: לא בסיכון** | 7 (FP) | 21 (TN) |

**יציבות:** ROC-AUC באימון 0.911, במבחן 0.911, ובאימות צולב של 5 קיפולים 0.885 ± 0.045. הפער קטן, ולכן אין התאמת-יתר.

**איזה מדד חשוב יותר? Recall.** False Negative פירושו מטופל בסיכון שנשלח הביתה בלי טיפול, וזה עלול לעלות בחיי אדם. False Positive עולה רק בבדיקות נוספות. לכן נעדיף Recall גבוה גם על חשבון Precision, ובמצב אמיתי כדאי להוריד את סף ההחלטה מתחת ל-0.5.

**הערה על הנתונים:** בחלק מהמשתנים הקשר הפוך לאינטואיציה הקלינית (תעוקה במאמץ ויותר כלי דם חסומים מופיעים אצל `target=0`). זה נובע מהגדרת עמודת `target` במאגר, והמודל לומד את מה שמופיע בנתונים.

### דשבורד HTML

`heart_dashboard.py` מאמן את המודל וכותב את המקדמים ופרמטרי הנרמול לתוך `heart_dashboard.html`. החישוב בדפדפן נותן בדיוק את אותה הסתברות כמו `predict_proba` של scikit-learn.

הדשבורד כולל:
- **מחשבון סיכון** – מזינים נתוני מטופל ומקבלים מיד הסתברות, סיווג (נמוך / אזור אפור / גבוה) ואת הנתונים שהשפיעו הכי הרבה. יש שלושה מטופלים לדוגמה למילוי מהיר.
- **מדדי ביצועים** – Precision, Recall, F1, ROC-AUC, מטריצת בלבול ועקומת ROC, עם סף החלטה שאפשר להזיז ולראות את הפשרה בין Precision ל-Recall.
- **הסבר המודל** – נוסחת הסיגמואיד, Odds Ratio לכל משתנה ושלבי הבנייה.

> המודל הוא כלי לימודי, מבוסס על כ-300 מטופלים בלבד, ואינו מחליף אבחון רפואי.
